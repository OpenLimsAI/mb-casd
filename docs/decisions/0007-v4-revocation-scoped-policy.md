# 固定 v4 撤销补丁与受限本人接口

候选基础为官方 v4.25.0 / `528a0213f01caf70b9f41009cbf7b2f67bdd67ec`。本仓库维护完整、可校验的补丁；不向上游仓库写入，也不自动升级既有实例。main 已有的 v3.152.0 撤销构建与 CI 继续保留。

最终 v11 补丁覆盖凭据 epoch、改密旧 IAM Cookie/令牌/待兑换码失效、存储故障拒绝和授权码／refresh 竞争。正常 refresh 轮换的旧 grant 消费与替换记录在一个事务中；失败回滚，重复消费者只允许一个提交。它不承诺已开始的所有 HTTP 请求在同一物理时刻取消。

本人策略和退出能力默认空／关闭。仅精确允许的客户端可用本人有效令牌获取固定状态与精简角色，不能指定其他用户、读取组织或获得管理权限。设备范围只接受可信当前会话，不能由浏览器任意指定 sid；全设备范围仍只影响本人。不得自动将 DCR 改为普通客户端，也不放宽 CORS。

协议驱动只接受两合成用户、五回环客户端和新空 tmpfs 库，入口在 `tests/iam_v4/`，没有真实用户或凭据。本人退出限定三客户端、本人策略限定两客户端；临时操作仍遵循实际环境审批。全部资源按拥有的 ID/标签清理，结果不明时停止而不盲目重建。

构建上下文采用显式文件边界。单独的否定目录规则会恢复子项，不能据此推断某个补丁文件缺失；`scripts/verify_build_context.py` 使用纯虚拟哨兵调用真实 Docker 导出上下文，验证必要输入存在、未审阅文件和 fixture 不进入上下文。

本地测试和最终镜像指纹见[候选验证](../verification/pr-candidate-20261105.md)。外部目录、MFA、SMTP找回密码正向、MySQL、离线JWT及所有真实设备组合未覆盖。共享 v3→v4 迁移必须另行备份恢复演练；只回退镜像不能当成数据库回滚。正式客户端配置、授权、部署及生产数据不在本次代码准备范围。
